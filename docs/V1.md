# Forge V1

**Status: complete and frozen, 20 October 2026.** V1 is the version described
here, as committed with this file. New work goes into V2.

Forge turns a plain-English description of one mechanical part into a
parametric design, builds it, measures the built part against what the brief
asked for, repairs what fails, and writes an STL ready to print. Every claim in
its report points at the measurement behind it, including the claims it could
not check.

---

## What V1 does

A run goes through these steps, each one recorded in `runs/<time>-<name>/`:

1. **Brief interpreter**: separates what the brief states from what it implies
   and what it leaves unsaid.
2. **Requirements engineer**: turns the brief into requirements, each bound to
   a measurement Forge can take on the built part. Forge then adds the claims
   the brief makes and the record missed: hole counts and positions, slot
   sizes, the part's own sizes, open tops, bends, rounded ends.
3. **Designer**: writes the part as a ForgeIR document: parameters and a
   feature graph of boxes, cylinders, profiles, extrusions, holes, bends,
   shells and booleans.
4. **Settle and check**: Forge corrects what it can be certain of without
   asking the model again (units, placements, roundings, interfaces), and
   sends back only what it cannot settle itself.
5. **Compile**: the implicit-geometry kernel builds the solid.
6. **Verify**: every requirement is measured on the built solid, and every
   gate ends PASS, FAIL, INCONCLUSIVE, BLOCKED, NOT_TESTED or NOT_APPLICABLE.
   Nothing undecided is counted as a pass.
7. **Repair**: a failing gate goes to the failure analyst, which writes small
   JSON patches; a change is kept only if the part still passes everything it
   passed before.
8. **Last look**: the model compares pictures of the part with the brief once
   before release.
9. **Output**: a print-quality STL (0.5 mm facets), pictures, the evidence
   graph and a live HTML view.

Runs use Claude Sonnet 5 through the Anthropic API, or a local model through
an OpenAI-compatible endpoint. The key is read from `ANTHROPIC_API_KEY` in the
environment and never written anywhere.

## What it was proven on

- **The test suite: 2,013 tests, all passing.** They include replayed real
  runs, fault injection, and every bug found in testing, each kept as a
  regression test.
- **The validation suite: 92 briefs in `validation/SUITE.md`**, graded
  automatically against the built part's measurements. Of the 91 graded,
  89 are OK. The other two (a hex bolt with a thread, a heart-shaped
  keychain) are for checking by eye.
- **A whole project, the Bionic Exo Arm:** a 3D-printed, actuator-driven
  elbow brace built from 13 separate parts, each a Forge brief written in
  plain English. All 13 were made, and each part's shape was checked against
  its brief by probing the built solid directly, not only through Forge's own
  checks. Most parts took 1 to 11 minutes and $0.30 to $1.00 on Claude
  Sonnet 5. The project found real bugs: a lug's semicircular end built
  square, a strip's rounded ends taken off, holes counted wrongly. Each was
  fixed at its source and kept as a test (see `docs/fixlist_v8.txt`).

## Running it

```powershell
$env:ANTHROPIC_API_KEY = "<your key>"     # this window only
.\run-design-claude.ps1 "A PLA spacer block 60 mm long, 30 mm wide and 10 mm thick ..."
```

Everything the run made is in `runs\<time>-<name>\`: open the `.stl` marked
`<- open this` in the listing. `views.png` shows the part from six sides, and
`run.txt` holds the full record.

Tests need no key and no network:

```powershell
$env:PYTHONPATH = "packages"
python -m unittest discover -s tests -p "test_*.py"      # everything, about 50 minutes
python -m unittest discover -s tests -p "test_kernel.py" # one file
```

### Briefs that work

From the arm's 13 parts:

- Give the whole part's sizes first: "a flat strip 110 mm long, 16 mm wide and
  2 mm thick".
- Place every feature with numbers measured from an end, an edge or the
  centre: "two 4.3 mm holes on the centreline, 8 mm and 28 mm from one end".
- Say which way things face when it matters: "on the top face", "from the
  +Y edge", "seen from above".
- Name each shape: "fully rounded ends", "ends in a semicircle of radius
  12 mm", "corners rounded to 3 mm seen from above".
- With no load case, say so: "Its strength is checked outside Forge, so there
  is no load case."

## Known limits

- **One part at a time.** Assemblies, mates and motion are not modelled.
- **Wording rules.** Forge reads briefs partly through hand-written wording
  rules. Wording they don't cover can slip past, and a change to one rule can
  break another. The test suite catches only the cases it holds.
- **Shapes said only in words** are measured only where Forge has a check for
  them (holes, slots, sizes, open tops, bends, rounded ends). Anything else a
  brief describes only in words can be wrong in a part that passes.
- **The last look can be wrong.** It once called square ends round. It is a
  second opinion, not a check.
- **Strength.** Only a few analytical checks: bearing, pin shear, bending of a
  straight bar. Briefs whose strength matters should leave it to an outside
  check.
- **Geometry.** The implicit kernel builds from a fixed set of features, and
  there is no B-rep and no STEP export.
- **English only**, and tuned and tested on Claude Sonnet 5.
- Cosmetic: one log line can say the last look "changed" a part that came out
  the same, and curved surfaces can show faint shading lines in a slicer.

## Toward V2

These are directions, not decisions; V2 starts with its own design document.

- **A spec, not wording rules:** the brief turned into an explicit list of
  features, sizes and relations that the user can confirm, every item measured
  on the built part automatically.
- **A real CAD kernel** (B-rep, for example OpenCascade), with STEP export and
  exact edges.
- **The last look as a warning only:** it can hold a part for a person, never
  release one.
- **Assemblies:** parts, mates and fits checked against each other, as the arm
  was by hand.
- **A measured baseline:** a blind test on frozen V1, so V2's error rate can be
  compared with numbers.
