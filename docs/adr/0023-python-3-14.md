# ADR-0023: CPython 3.14 is the floor and the runtime

**Status:** Accepted · **Date:** 2026-11-10 · Stage 4b.0a

## Context

`pyproject.toml` says `requires-python = ">=3.10"`; the cloud runs 3.13 and
the owner's laptop 3.12. As of 10 November 2026: CPython 3.15 is the newest
(3.15.0, 9 October 2026), 3.14 is at 3.14.10 with bug fixes to October
2027 and security fixes to about 2030. OCP's wheels stop at 3.14 (no cp315,
no free-threaded build); NumPy 2.5 and SciPy 1.18 need 3.12 or later and
already ship 3.15 and free-threaded wheels.

## Decision

- **`requires-python = ">=3.14"`**, and CPython 3.14 (the normal build) as
  the runtime on the laptop, in the cloud and in Docker, from 4b.0a′'s
  second sub-step on, after the kernel's replay (ADR-0022) and 4b.0b
  (ADR-0035): every regression, the 2,000 held-out seeds and a fixed 2,000
  of the counted seeds replayed on the restructured code, any difference
  sending it to a whole replay. The owner
  installs CPython 3.14 on the laptop once; the steps go in the developer
  guide.
- **CI also runs the trust core alone on 3.15 and on free-threaded 3.14t**,
  which it supports already (pure Python, NumPy and Forge's own compiled
  core, ADR-0024, built separately for the free-threaded interpreter, as
  an `abi3` wheel won't load there), so the move is ready the day OCP
  ships cp315 wheels.
- **Parallelism** comes from worker processes and from the compiled core
  releasing the GIL (ADR-0024), not from the free-threaded build, until OCP
  supports it.

## Consequences

Forge may use 3.14's language and library (deferred annotations, template
strings, `compression.zstd`, the incremental collector) everywhere. The
laptop's Python changes once. A Python move is a replay of the regressions,
like a kernel move.

## Alternatives

3.15 now: blocked by OCP. 3.13: older, with nothing gained. Rejected.
